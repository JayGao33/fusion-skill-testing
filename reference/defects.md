# 缺陷类型库

跨 skill 复用的缺陷分类记忆。来源：多轮 skill 实测沉淀（D1-D14 / N5-N6 / 审查 12 项）+ 通用 skill 写作规范词汇表。测试中发现的**新类型**按同样格式追加，同类不重复记录。

严重度：🔴 P0 流程正确性/对称性硬伤 · 🟠 P1 可靠性/真实性 · 🟡 P2 覆盖不全/体验。

---

## 行为层缺陷（逐路径测试中发现）

| 类型 | 严重度 | 现象 | 典型证据 | 修复方向 |
|:--|:--|:--|:--|:--|
| **跳步** | 🔴 | 首条消息带阶段词/意图词时跳过前置闸门 | 文档只定义"流程中"规则，无首条消息规则 | 补"首条消息仍从 ① 起，阶段词仅作提示" |
| **占位符泄漏** | 🔴 | 格式占位符被当真实内容输出（如「词」） | 关卡出口模板写死「词」代替真实回复词 | 删除占位符写法，或强制替换后输出 |
| **复读** | 🔴 | 交付物已产出仍重跑（跳步/插话后） | 无"认领/续跑/跳过"状态对账规则 | 补状态对账：已产出 → 认领 + 一句话跳过 |
| **分支不对称** | 🔴 | 声称覆盖的分支缺少对等设计 | 主分支 5 关 + 前置决策，次分支 2 关无前置决策 | 对齐分支结构，或明说轻量设计是意图 |
| **引用错位** | 🔴 | 「见 X §N」指错章节，语义完全不符 | 判定规则指到 §6，实为 §8；注释与条件自相矛盾 | 修正引用；注释与正文交叉核对 |
| **导航缺失** | 🟠 | 用户主动导航（回退/重做/跳关/退出）无规则 | 输入规则只有菜单回复，无导航动词 | 补导航动词 → 动作映射 |
| **溯源缺失** | 🟠 | 时效/外部信息无核验要求 | 信息溯源条款只覆盖部分对象类型 | 补"无法确认则联网核验并标注来源" |
| **纸面自检** | 🟠 | 自检无硬机制且与自身规则矛盾 | 落成自检要求与模板实际不符 | 让自检项可被机械验证（脚本/清单） |
| **临场 reinvent** | 🟠 | AI 自造 skill 没有的结构接住用户 | 测试跑出 spec 之外的闸门/关卡/流程 | 视为 spec 缺口证据：补规则或明确拒绝 |
| **菜单漂移** | 🟡 | 菜单格式不一致（数字/回复词/占位） | 一处菜单有编号，另一处没有 | 统一菜单模板，纳入落成自检 |
| **覆盖缺行** | 🟡 | 选型表/模板缺分支行 | 模板对照表只覆盖部分对象类型行，缺其他类型行 | 补全分支行与对应模板 |
| **表述矛盾** | 🟡 | 对外文案自相矛盾 | "不用记任何词"随后又列三个要说的词 | 改述消除矛盾 |
| **规则冲突** | 🟠 | 文档内部两条规则互相矛盾，模型每次取舍不同（区别于"表述矛盾"的文案层——这是规则层） | "默认输出简洁版（一个表格）"vs"标签/元认知（必做）"；跨文件对同一输入给不同路径 | 统一到单一权威处；矛盾处显式协调（如规定简洁版保留必做要素） |
| **平台错配** | 🟠 | 跨平台 skill 写死特定 OS 能力，无平台条件说明 | 日历提醒只写 `macos-calendar` skill，无 Windows/Linux 替代路径 | 加平台条件分支（替代方案或降级话术） |
| **自更新指令** | 🟠 | skill 指令模型修改 skill 自身文件（追加/更新），无用户授权流程 | 资源库"搜索并将结果追加到此文件"；且与随附风险声明自相矛盾 | 删除自更新指令，或改为"先征求用户同意再写" |
| **触发过宽** | 🟠 | description 泛化，无关请求也被触发（原则 2） | 描述覆盖范围大于实际能力 | 收紧描述，明确能力边界 |
| **触发过窄** | 🟡 | 该调不调（原则 2） | 描述缺触发词/场景词 | 补触发词与场景 |
| **缺降级路径** | 🟠 | 异常输入/资源缺失时无优雅降级（原则 4） | 失败直接报错/裸奔 | 补降级话术与替代路径 |
| **缺幂等** | 🟠 | 重复操作结果不一致（原则 4） | 重做/连发产生不同结果 | 定义幂等行为 |
| **组合风险** | 🟠 | 与相邻 skill 联动时越权/循环/成本复利（原则 5） | 权限叠加越权、调用成环 | 组合级评测，定义边界 |
| **运行依赖缺失** | 🟠 | 依赖外部工具/运行时但无前置检查与降级（原则 4） | 脚本直接调用不存在的 CLI/目录，报错裸奔；文档未声明依赖 | 脚本加前置检查 + 文档补依赖说明与降级指引 |
| **安全红线缺失** | 🟠 | 危险操作类 skill 无可妥协的绝对 guardrail | 清理类工具无"永不直接删除/只隔离"红线，安全靠 CLI 语义兜底 | 补一条不可妥协的绝对红线 |

## token 效率缺陷（执行层浪费，评级见 [token-efficiency.md](token-efficiency.md)）

| 类型 | 现象 | 典型证据 | 修复方向 |
|:--|:--|:--|:--|
| **全量重读** | 每次运行重读全部输入/文件而非按需 | 规则写"先读全部 reference"或每步重读 | 改按需加载 + 状态保留 |
| **重复计算** | 同一结果算多次 | 同一次运行重复调用同一工具/搜索同一对象 | 一次调用，结果复用 |
| **可合并未合并** | 多个可合并的中间步骤未合并 | 多次小调用代替 1 次批量调用 | 合并调用/批量读取 |
| **无必要输出** | 输出含可省长内容/重复已产出内容 | 每段输入重复前缀标注、复读交付物 | 简化输出、认领跳过 |
| **复跑已完成** | 交付物已产出仍完整重跑（与「复读」同源，token 视角） | 状态对账缺失导致重跑 | 认领 + 一句话跳过 |

## 安全缺陷（安全红线级，判据即本表）

| 类型 | 严重度 | 现象 | 典型证据 | 处理 |
|:--|:--|:--|:--|:--|
| **恶意行为** | 🔴 红线 | 挖矿/后门/偷连未知 API/数据外传 | 脚本含可疑外联或挖矿载荷 | 终止交付建议 |
| **高危操作无护栏** | 🔴 红线 | 删除/清空类操作无 dry-run/确认/隔离机制 | 清理类 skill 直接删除无 quarantine | 终止交付建议；补护栏可复评 |
| **硬编码凭据** | 🔴 红线 | API key/token/私钥/密码明文在包内 | 脚本含 sk-xxx / ghp_xxx / 私钥块（formcheck ⑦ 检出） | 终止交付建议；移出凭据可复评 |
| **越权权限** | 🔴 红线 | 请求与任务无关的高权限 | 文档处理 skill 要求系统级删除权限 | 终止交付建议；最小化权限可复评 |
| **自更新指令** | 🟠 | skill 指令模型修改 skill 自身文件且无用户授权（已有类型，红线语境升级） | "搜索并将结果追加到此文件" | 删除或改为先征求同意；**无授权流程时按红线处理** |
| **海外依赖不可用** | 🟠 | 核心功能依赖海外 API，国内无法直接跑通 | 硬依赖海外 API | 补国内替代或降级路径；无法补 → 记问题 |

> 红线处理流程：formcheck ⑦ 扫描命中凭据/危险模式 → 人工复核确认 → 触碰红线即**终止交付建议**（诊断继续、数据照收），报告注明"未通过安全红线（理由）"；疑似但证据不足按「缺陷必须带证据」记为待核实，不直接判红线。修复后重跑 gate（步骤 1.8）即恢复可交付判定。

## 质量层缺陷（静态审查中发现，借用通用 skill 写作规范词汇）

| 类型 | 判据 | 修复方向 |
|:--|:--|:--|
| **premature completion**（提前完成） | 步骤完成标准模糊，AI 可提前宣称完成 | 先磨 completion criterion（可检查、穷尽）；仍模糊才拆分隐藏后续步骤 |
| **duplication**（重复） | 同一含义在多处各写一遍 | 收敛到单一权威处，其余留指针 |
| **no-op**（废话） | 该行不改变模型默认行为 | 删除整句（不是删词留句） |
| **negation**（否定引导） | 用"不要 X"引导，反而激活 X | 改正面描述目标行为 |
| **sediment**（沉积） | 过期/失效旧层未清理 | 按 relevance 逐行清理 |
| **sprawl**（臃肿） | 太长（即使每行都有效） | 渐进披露：参考下沉到外置文件 |
| **完成标准模糊** | completion criterion 不可检查（"理解到位"） | 改成可检查、穷尽的表述（"每个修改的模型已对账"） |
| **双写同源** | 同一信息在 engine/companion 各参数化一遍 | 一处权威，另一处只写指针 |
| **参数幻觉** | 写"可配置参数"但 skill 无运行时读配置 | 删除，或降级为单行指针 |
| **可算法化未替代** | 长散文规则/重复判断/人工枚举可被确定性算法替代，替代后**同时**更经济（成本更低）且更精确（准确性更高），却仍以自然语言保留 | 判据：双条件（更经济 ∧ 更精确）**同时满足才替代并删除原文**；任一不满足则保留原文（防"为算法而算法"） | 提取为规则表/脚本/数据表，删除原文 |
| **为算法而算法** | 算法化未带来双条件收益，反而增加维护面 | 替代后仅更精确但不更经济，或仅更经济但不更精确 | 回退保留原文 |
| **上下文指针措辞弱** | 必须内容背后的指针含糊，触发不可靠 | 先磨措辞；失败才把内容拉回内联 |

## 模块×维度判据（静态审查覆盖 · 唯一权威）

- **×正确性**：本文件规则与其声称的功能是否一致？流程线状态有无缺失（如某分支在状态机无映射）？
- **×引用**：本文件所有「见 X §N」/链接应指与实指一致？
- **×UX**：本文件是否影响用户可感知的复杂度 / 反馈质量 / 入口可见性（如某模式入口是文字不是编号项）？
- **×过度设计**：本文件机制是否冗余？参数化是否必要？文档化是否超出机制本身？**是否有可算法化替代（更经济∧更精确）却保留原文的内容？**
- **×token效率**：本文件描述的规则是否导致执行多花 token（全量重读/重复计算/可合并未合并/无必要输出）？四级评级与量化指标见 [token-efficiency.md](token-efficiency.md)。
