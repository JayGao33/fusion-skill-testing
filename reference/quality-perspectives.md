# 质量五维视角（可选深度总结）

> **按需参考文件，非流程必读**：仅当用户要求「五维质量总结 / 深度总结」时查阅。常规测试走 SKILL.md 流程，不因本文件存在而改变内部检测。

五维从**用户视角**回答五个问题：能不能放心用、能不能稳定用、该不该在这场景用、能不能被理解与维护、是否真正解决问题。内部检测机制是执行者，五维是报告语言（需要时才导出）——不新增平行的重复检测。

## 五维总表

| 维度 | 核心问题（用户视角） | 检测机制（内部） | 适用范围 | 边界与异常 |
|:--|:--|:--|:--|:--|
| **可信度** | 能不能放心用 | 步骤 1.8 安全审查 + formcheck ⑦ 安全初检 | 所有 skill，**执行测试第一步** | 触碰安全红线 → **判不可交付**，终止测试与全部评级 |
| **可靠性** | 能不能稳定用 | 失败路径（步骤 3.6）+ ×正确性（流程线状态缺失）+ 幂等/异常反馈检查 | 有运行行为或状态机的 skill | 无法真实运行（外部依赖缺失）→ 降级静态审查 + 标注「行为层未实测」 |
| **适用性** | 该不该在这场景用 | 触发与拒识路径（步骤 2.4）+ 缺陷「触发过宽/过窄」+ description 边界核对 | 所有 skill | 无触发声明（无 frontmatter）→ 记缺陷并注明「自动触发失效，仅手动可用」 |
| **规范性** | 能不能被理解/维护/复用 | 质量镜头（步骤 1.5：sprawl/渐进披露/duplication）+ 限制说明完整性核对 | 所有 skill | 文档过载 vs 缺失的判定以「信息层次」判据为准，不因「文档多」加分 |
| **有效性** | 是否真正解决问题 | 基线对照（步骤 3.7）+ 有效性核对（步骤 4）+ 结果/输出完整性检查 | 所有 skill，**依赖对照实验** | 无法构造 no-skill 参照组 → 标 N/A 并说明；依赖缺失时 skill 加持 < 裸 prompt 的场景必须如实记录 |

## 安全红线（可信度维度，最高优先级）

红线清单与判定/处理流程见 [defects.md](defects.md#安全缺陷)——**唯一权威，不在此复述**（防双写同源）。触碰任一红线 → **判不可交付**，不再评其他维度；疑似红线但证据不足 → 按「缺陷必须带证据」记为待核实，不直接判红线。

## 报告输出（report.md 模板「五维质量总结」节）

每维输出：评分（1-5，参考内部证据）+ 一句依据 + 内部证据指针。整体评级规则：

- 触碰安全红线 → 不评分，直接「未通过安全红线（理由）」
- 内部存在 P0 → 整体「待修复」，各维可给但不作为可用信号
- 无法实测的维度 → 标 N/A + 原因（评分是观察坐标，不是终局裁判）

## 与九原则的关系

| 五维 | 九原则 | 关系 |
|:--|:--|:--|
| 可信度 | 4 面向失败设计（安全子集）+ 安全红线 | 九原则 4 的「兜底/熔断」是可信度的正面表述 |
| 可靠性 | 4 面向失败设计 + 1 底线优先 | 一致，可靠性是 4 的另一种命名 |
| 适用性 | 2 该答才答 | **同一判据** |
| 规范性 | 3 认知减负 + 8 上线只是开始 | 规范性的「可维护/可复用」是 8 的文档侧 |
| 有效性 | 6 实证试金石（基线对照） | **同一机制**：no-skill 参照组 = 基线对照 |

> 关系说明：九原则是「内生质量标准」，五维是「用户视角的外部观察口径」——检测时不重复执行，总结时按两套口径分别输出（内部缺陷清单 + 五维总结）。
