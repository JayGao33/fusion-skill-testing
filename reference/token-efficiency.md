# token 效率测评

衡量 skill 实现既定功能时所走路径是否最优——同一结果，是否比必要路径多花了 token。**只对功能正确的 skill 评级**；存在 P0 缺陷时标 N/A（先修正确性，再谈效率，见 SKILL.md「先对后省」）。

## 评价尺度（四级）

| 等级 | 定义 | 判断依据 | 可观察量化指标 |
|:--|:--|:--|:--|
| 🟢 **符合最优路径** | 执行步骤 = spec 声明的最小必要步骤，零冗余 | 每次运行只做必要的事：一次读取、一次计算、一次输出，无重复已产出内容 | 工具调用数 = 必要数；重复读取 = 0；中间步骤 = spec 最小步骤数；输出无整段可省内容 |
| 🟡 **基本符合** | 存在 ≤2 处轻微冗余，不影响功能与可读性 | 冗余是噪音级：一次可合并的读取、多一次校验、极次要的赘余输出 | 冗余调用 ≤2；重复读取 ≤2 文件；输出含 ≤1 段可省内容 |
| 🟠 **存在明显冗余** | 冗余 ≥3 处，或存在系统性可合并而未合并的中间步骤 | 每次运行固定多花 token：重复读取、重复计算、整段可省输出 | 冗余调用 ≥3；重复读取 ≥3；存在整段可省输出；步骤数 > 必要数 1.5 倍 |
| 🔴 **严重浪费 token** | 结构性低效：路径设计与最优有系统性偏差 | 每次运行都全量重读/重跑已完成步骤/无法避免的重复路径 | 重复读取 ≥50% 输入；存在「重跑已完成步骤」行为；步骤数 > 必要数 2 倍 |

## 可观察指标清单

| 指标 | 最优信号 | 浪费信号 |
|:--|:--|:--|
| 工具调用次数 | 一次调用返回全部所需 | 多次小调用可合并；同一输入重复调用 |
| 文件读取范围 | 按需加载（只读当前分支需要的 reference） | 每步全量重读所有文件 |
| 重复计算 | 结果算一次，后续复用 | 同一结果重复计算 |
| 中间步骤数 | = spec 声明的最小步骤数 | 存在可跳过/可合并的中间步 |
| 输出冗余 | 无重复已产出内容 | 复读已产出交付物、每段输入重复前缀标注、整段赘余 |
| 分支复杂度 | 可合并分支已合并 | 重复分支逻辑、可参数化而未参数化 |

> 量化口径：以同一次运行的**实际执行记录**为准（工具调用序列、读取的文件清单、输出内容），不凭印象估算。路径矩阵的逐路径记录即数据来源（SKILL.md 步骤 3）。

## 示例：功能正确但路径非最优 vs 功能正确且路径最优

> 判定要点：两组路径**功能都正确、交付物相同**，只比到达同一结果花的 token——多读的文件、多调的次数、多输出的段落，都是可量化的差值。

**示例 1 · 复用检测（状态对账）**
- 🟠 非最优（功能正确）：流程中「下一步」机械重跑上一关——交付物已产出仍完整重跑一遍，最终结果正确但 token 翻倍。
- 🟢 最优：先检测交付物已存在 → 认领 + 一句话跳过，不再重跑。
- 对照：状态对账缺陷修复前（复读）vs 修复后（认领跳过）。

**示例 2 · 按需加载**
- 🟠 非最优（功能正确）：每个关卡都重新加载全部 reference 文件（10 个全读，实际只用 2 个）。
- 🟢 最优：参考资源表标注「按需加载，不预先读取」，按分支只读当前需要的文件。

**示例 3 · 重复计算**
- 🟠 非最优（功能正确）：同一次运行对同一输入重复调用同一工具 3 次（如重复搜索同一书名），3 次结果一致。
- 🟢 最优：一次调用，结果在后续步骤复用。

**示例 4 · 输出冗余**
- 🟠 非最优（功能正确）：每段输入都完整重复同一标注前缀（连发 5 张图刷 5 遍「识别自图片，请核对」）。
- 🟢 最优：首张完整标注，后续简化为「（同上）」。

## 与既有维度的关系

- **与 ×过度设计互补不重叠**：过度设计看**设计层**（机制/参数/文档是否冗余），token 效率看**执行层**（跑起来是否多花 token）。过度设计是 token 效率的静态诱因之一，但动态执行浪费（重复读取、重跑已完成步骤）只由 token 效率维度捕捉。同一现象若既冗余又浪费，在缺陷清单各记一条、评级各算一档。
- **与「复读」缺陷的关系**：复读（状态对账缺失）同时是正确性缺陷（行为错误）与 token 浪费。分级时按正确性记 P0；token 效率维度负责量化其浪费程度并给评级——两者不冲突，是同一现象的两个视角。
- **与缺陷分级并行**：缺陷分级回答「要不要修、多急」，token 效率评级回答「修完后这条路径有多省」；评级结果不改变缺陷的 P0/P1/P2 结论。
