# fusion-skill-testing · Skill 质量测试

> © 2026 Bangbang fusion，CC BY-NC-SA 4.0 授权

把一个 skill（单文件或多文件包）测穿——静态审查 + 全路径行为测试 + 分级修复 + 回归，最后给你一份带证据的缺陷清单和"能不能放心用、哪里要修"的结论。全平台通用，不绑定任何特定 agent 平台的审核规则。**纯本地运行、零联网**——不依赖任何外部服务，国内环境开箱即用。

## 它解决什么问题

| 场景 | 你遇到的坑 | 它怎么做 |
|:--|:--|:--|
| 刚写完一个新 skill | 自己写的总觉得没问题，一用就露馅 | 静态审查先抓规则/引用错，再跑全路径看真实表现 |
| 改完一个老 skill | 修了 A，不知道有没有带崩 B | 回归测试重跑关键路径，确认没有新回归 |
| 老 skill 想体检 / 打磨上线 | 不知道质量到底行不行 | 按成熟度标准打分（含 token 效率四级评级），直接给"可用 / 待修复" |
| 担心"假通过" | AI 临场补救充数，看着像过了 | 有效性核对区分"忠于 spec"还是"临场 reinvent"，后者不算通过 |

## 适合谁

- 在任何 agent 平台上写、改、维护 skill 的人（如 WorkBuddy、Claude、自建环境）
- 想把 skill 打磨到好用、能放心交付的人
- 团队里有共享 skill，想立一套统一质检标准的人

## 怎么开始（不用学，直接说）

你不必会读代码——报告每节都有白话总结，"可用 / 待修复"的结论足够你做决策；技术细节是给修的人看的。

- "测试这个 skill" → 测当前或指定的 skill（标准档，默认）
- "快速测一下 / 秒查" → 只查格式门禁（gate 档，秒级，像 lint）
- "深度测 / 全面审计" → 完整深度评测（含基线对照 + 五维总结）
- "帮我回归测试一下" → 修复后重跑，确认收敛
- "这个 skill 能放心用吗？" → 跑完整流程，给结论
- 你不点名时，它默认测"当前对话涉及 / 最近改过的"那个 skill

**三档怎么选（体检类比，看一句就够）**

| 档位 | 一句话 | 什么时候用 |
|:--|:--|:--|
| 快速（gate） | 量体温：秒级查格式门禁 | 创作早期、每次迭代后当 lint 跑 |
| 标准（默认） | 常规体检：格式 + 全路径行为 + token | 大多数时候 |
| 深度 | 全项 + 影像：再加基线对照 + 五维总结 + 实用性分 | 发布/上架前的审计——顺带看清"这工具值不值得做、实际省了多少步" |

**有 Python 和没有 Python，差在哪（降级透明）**

| 检查层 | 有 Python | 没有 Python |
|:--|:--|:--|
| 形式层（frontmatter/链接/锚点/孤儿/安全） | 脚本自动跑 | AI 按检查项人工核对，慢些、可能漏细节 |
| 行为层（逐路径/失败路径/回归） | 照跑 | 照跑 |
| 结论可靠性 | 完整 | 形式层结论打点折，报告会标注"未跑脚本" |

超大 skill 包（>50 文件）自动降级为门禁 + 主流程测试，或按 FAQ 里的"分批法"拆开测——边界先说清，不藏着。

## 触发它很简单

- 它靠触发词启动（测试这个 skill、审查 skill、帮我测一下、检查一下、评估一下、诊断一下、帮我看看这个 skill 行不行、体检一下、skill 有没有问题、回归测试），说一句大白话它就接
- 装好即用，不需要先建任何配置
- 真干活时它会自己跑 `tools/formcheck.py`、读 `reference/` 里的标准，你不用管

## 快速示例（一段真实对话）

**你**：测试这个 skill
**它**：好，开始测 my-skill（标准模式）。先跑形式层检查，发现 2 个问题：
1. 🔴 SKILL.md L24 有条链接指向不存在的文件（P0，必须修）
2. 🟡 README 里菜单格式不统一（P2，小问题）
形式层之后我会跑全部路径的行为测试，几分钟出完整报告。

**你**：严重吗？现在能用吗？
**它**：有 1 个 P0，结论是「待修复」——链接断掉意味着模型执行时会读到空内容，建议先修。每条缺陷都标了改哪个文件、怎么改，照着改就行。

**你**：修好了，帮我回归一下
**它**：重跑修复路径 + 相邻路径 + 主流程——P0 已消除，无新回归，结论「可用」。报告已生成，含缺陷清单和证据行号。

> 三档模式（快速/标准/深度）怎么选，见上面"怎么开始"的体检类比表。

## 第一次使用 · 手把手走查（从零到报告，5 分钟）

以"刚写完 my-skill，第一次测"为例，完整走一遍：

1. **开口**：说「测试这个 skill」。它会自动认出当前对话里的 my-skill，按标准档开测——先用脚本查格式门禁。
2. **看格式层结果**：它报出 2 个问题——`SKILL.md L24 链接目标不存在`（🔴 P0）和 `README 菜单格式不统一`（🟡 P2）。看不懂？每条都有人话解释（见 FAQ「报错人话对照」）。
3. **决定怎么处理**：有 P0 → 结论「待修复」。不用慌，这不代表 skill 不能用，只是有硬伤要先修；P0 的修复方法写在缺陷清单里，照抄即可。
4. **照着改**：每条缺陷都标了「改哪个文件、怎么改」。改完说一句「帮我回归一下」。
5. **看回归结论**：重跑修复路径 + 相邻路径 + 主流程——P0 已消除、无新回归 → 结论「可用」。

> 全程你要做的只有三件事：说一句话 → 看结论 → 改。报告里的技术细节是给修的人看的，你只需要看最后的「可用 / 待修复」。

## 什么时候不该用

- **不是 skill 质量相关**：写代码、翻译、普通问答——它不接，也别硬让它测
- **宿主读不了文件/跑不了脚本**：只能降级做静态审查（凭模型知识 + 你贴出的内容），行为层测不了
- **目标不是 skill 包**：普通文档、网站、数据表不是它的测试对象
- **纯主观创意评价**：没有客观判据的东西，它测不了"好不好"

## 写 skill 避坑自查清单（作者视角 · 新手可跳过）

以下两节是写给 **skill 作者**的进阶内容——你只是用它来测别人的 skill，直接跳过不影响任何使用。

写的时候自查这 8 件事，能躲掉大部分返工（完整判据见 reference/defects.md）：

1. **跳步**：首条消息带"直接给我第 2 步"会跳过前置吗？→ 补「首条消息仍从入口起，阶段词仅作提示」
2. **占位符泄漏**：模板里写死的"词"会被当真实内容输出吗？→ 强制替换后再输出
3. **复读**：交付物已产出，会重跑还是认领？→ 补状态对账
4. **双写同源**：同一规则是不是在两处各写一遍？→ 一处权威，另一处只留指针
5. **参数幻觉**：文档写了"可配置参数"，脚本真的读它吗？→ 没读就删，或降级为一行指针
6. **完成标准模糊**："理解到位"算完成？→ 改成可检查、穷尽的表述
7. **触发过宽/过窄**：该调的没提、不该调的进来了？→ 触发词对准能力边界
8. **缺降级**：用户环境缺东西时会报错裸奔吗？→ 补降级话术与替代路径

## 常见反模式速认（作者视角 · 新手可跳过）

接上一节：自测清单是"你该检查什么"，下面是"错误长什么样、测试怎么抓到你"——写的时候对照着避雷（完整判据见 reference/defects.md）：

| 反模式 | 错误写法（一眼识别） | 测试怎么抓 | 正确写法 |
|:--|:--|:--|:--|
| **跳步** | 只写了"流程中"的规则，没写"首条消息"的规则 | 首条消息带"直接给我第 2 步"，模型跳过前置直接出活 → 🔴 P0 | 补「首条消息仍从入口起，阶段词仅作提示」 |
| **占位符泄漏** | 回复模板里写死「词」代替真实内容 | 输出里出现"「词」"而不是用户要的东西 → 🔴 P0 | 删掉占位符写法，或强制替换后再输出 |
| **复读** | 交付物已经产出，没有"认领/跳过"的状态对账 | 用户插话后模型把整件事重跑一遍 → 🔴 P0 | 补状态对账：已产出 → 认领 + 一句话跳过 |

> 这三个坑各占真实测评里 P0 的大头，先躲它们，再谈优化。

## 常见问题 FAQ

- **测一个 skill 要装什么？** 什么都不用装。宿主能读文件、跑 Python 就行；纯离线也能测（凭模型知识 + skill 文件）。
- **报告里的 FAIL 看不懂怎么办？** 每条 FAIL 都带"文件+行号"和修复提示；还看不明白，把报错原文贴给 AI 让它解释，或看下面的术语速查。
- **没有 Python 环境能测吗？** 能。形式层检查会降级为 AI 人工核对（按 SKILL.md 的检查项逐项核），效果略打折但流程照跑。
- **需要联网吗？** 不需要，纯本地。只有遇到时效性/外部信息需要核实时才会联网。
- **只能测 WorkBuddy 的 skill 吗？** 不是。任何 agent 平台的 skill 包都能测，只要目录里有 SKILL.md。
- **报告里的 P0/P1/P2 是什么意思？** 缺陷严重度分级，见术语速查。
- **测完说"待修复"，我能直接改吗？** 能。每条缺陷都标了"改哪个文件、怎么改"，改完说一声"回归测试"即可验证收敛。
- **测出来的结论可信吗？** 它把"临场 reinvent"（AI 临时补救充数）和"忠于 spec"分开算，后者才算通过——专门防"假通过"。
- **怎么判断一个 skill 到底好不好？** 看五件事：门禁（有没有 P0 硬伤）、可靠性（出错时会不会优雅降级）、适用性（该触发时触发、该拒时拒）、规范性（文档能不能看懂）、有效性（是不是真按规则跑、有没有"假通过"）。报告把这五件事浓缩成一个结论：**可用 / 待修复**。
- **一次能测多大的 skill？** 50 个文件以内、SKILL.md 400 行以内 → 全流程测。更大的包有两种走法：① 快速走法——先测门禁 + 主流程，完整行为层按你指定的子集测；② 分批走法——按子目录/模块把包切成 2-3 批，每批单独出一份子报告，最后合并结论。二选一，别硬塞。
- **报错人话对照（高频 FAIL 一看就懂）**
  - `链接目标不存在` → 文档里点了个文件名，但那个文件不在包里。多半是文件改名了、挪位置了，或大小写对不上。
  - `锚点不存在` → 链接带着 `#小标题` 跳转，但目标文件里找不到这个小标题。多半是标题改了、链接没跟着改。
  - `孤儿文件` → 有个文件躺在包里，但没有任何文档提到它——模型永远不会读到它。
  - `frontmatter 缺失` → SKILL.md 开头缺身份说明，模型认不出这是个 skill、不知道什么时候该用它。

## 术语速查

| 术语 | 含义 |
|:--|:--|
| **P0 / P1 / P2** | 缺陷严重度：P0 门禁（必须修，存在即不可交付使用）；P1 可靠性/真实性问题；P2 覆盖不全/体验问题 |
| **token 效率四级** | 🟢 符合最优路径 / 🟡 基本符合 / 🟠 明显冗余 / 🔴 严重浪费；有 P0 缺陷时标 N/A（先对后省） |
| **忠于 spec vs 临场 reinvent** | 按 skill 文档写的规则跑通 = 忠于 spec；AI 自造流程临时补救 = reinvent，**不算通过** |
| **gate（快速模式）** | 形式层 + 安全审查 + 交叉引用 + 描述真实性，秒级，像 lint |
| **五维质量总结** | 可信度 / 可靠性 / 适用性 / 规范性 / 有效性——用户要求深度总结时的可选导出 |

> README 是给你看的；`SKILL.md` 和 `reference/` 是 AI 的内部规范，你不用读。

## 它怎么保证"测得准"

- **测试者不替 spec 做主**：路径怎么走由 skill 文档决定，不是由"更合理"的流程决定
- **缺陷必须带证据**：现象 + 文件行号，没证据的怀疑只写进报告、不算缺陷
- **分数是体温计不是靶子**：评级只用来定位问题，不贴终身标签，也不为"好看"去优化目标 skill
- **有效性优先于数量**：10 条忠实跑通的路径，胜过 20 条临场补救的"通过"
